### D-06. Выдача клиентской сессии только после подтверждения почты

**Контекст:** Знание адреса электронной почты не подтверждает владение им. Если сервер создаёт авторизованную сессию до успешной проверки кода, посторонний сможет открыть заявки клиента и принять решение о ремонте от его имени.

**Решение:**

- Сервер создаёт сессию только после успешной проверки одноразового кода, отправленного на почту клиента. До этого защищённые endpoint недоступны.
- Код хранится в виде хэша, имеет срок действия и ограничение попыток, используется один раз. Ответ на запрос кода одинаков для существующего и неизвестного адреса.

**Обоснование:** Знание адреса не доказывает владение почтой. Одноразовый ограниченный по времени код предотвращает вход только по чужому адресу и повторное использование кода.

**Связанные угрозы:** [T-01](../threats/T-01.md).

**Связанные требования:** [SR-AUTH-01](../security-requirements/auth/SR-AUTH-01.md), [SR-AUTH-04](../security-requirements/auth/SR-AUTH-04.md), [SR-REPAIR-06](../security-requirements/repair/SR-REPAIR-06.md).

**Будущая проверка:**

- **Условие:** Код отправлен на почту существующего клиента.
- **Действие:** Попытаться войти без кода, с неверным, истёкшим и уже использованным кодом, затем — с актуальным.
- **Ожидаемый результат:** Сессия создаётся только для актуального кода и только один раз; остальные попытки не дают доступа к заявкам.

**Ограничения и последствия:** Решение не защищает при компрометации почтового ящика. Ограничение попыток не должно позволять надолго заблокировать вход клиента.
