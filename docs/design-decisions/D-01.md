### D-01. Изменение ролей

**Контекст:** Учетные записи могут продолжить использовать права после отзыва ролей.

**Решение:** Не хранить роль в JWT токене клиента, а запрашивать права из базы данных для каждого запроса.

**Обоснование:** Данный способ позволяет сразу при отзыве прав ограничить доступ к функциям, к которым доступа быть не должно.

**Связанные угрозы:** [T-03](../threats/T-03.md)

**Связанные требования:** [SR-AUTH-07](../security-requirements/auth/SR-AUTH-07.md)

**Будущая проверка:**

- **Условие:** учетная запись с ролью админ, которую только что отозвал суперпользователь.
- **Действие:** попытка совершить действие доступное только админу, например создать заявку на ремонт.
- **Ожидаемый результат:** отклонение доступа с кодом ошибки 403 Forbidden.

**Ограничения и последствия:** Данное решение может добавить определенную задержку к запросам, где необходимы дополнительные права.
