# SR-REPAIR-09

## Утверждение
Для заявки используются состояния `DIAGNOSING`, `WAITING_FOR_CLIENT`, `REPAIRING`, `READY` и `CANCELLED`. Разрешены только переходы, соответствующие завершению диагностики, решению клиента, ранней отмене или завершению ремонта.

## Критерий приёмки
- Пользователь с ролью `ENGINEER` завершает диагностику и переводит заявку из `DIAGNOSING` в `WAITING_FOR_CLIENT`: сервис выполняет переход.
- Клиент подтверждает ремонт собственной заявки в `WAITING_FOR_CLIENT`: сервис атомарно сохраняет согласие и переводит заявку в `REPAIRING`.
- Клиент отклоняет ремонт собственной заявки в `WAITING_FOR_CLIENT`: сервис атомарно сохраняет отказ и переводит заявку в `CANCELLED`.
- Клиент рано отменяет собственную заявку в `DIAGNOSING`: сервис атомарно сохраняет отмену и переводит заявку в `CANCELLED`.
- Пользователь с ролью `ENGINEER` завершает ремонт и переводит заявку из `REPAIRING` в `READY`: сервис выполняет переход.
- Для заявки в `READY` или `CANCELLED` запрошен новый переход: сервис возвращает ошибку конечного состояния.
- Запрошен любой другой прямой переход между состояниями: сервис возвращает ошибку недопустимого перехода.

## Внутреннее обоснование
- Актив: состояние заявки и достоверность сведений о ходе ремонта.
- Роль: инженер, клиент.
- Взаимодействие: завершение диагностики, принятие решения клиентом, выполнение ремонта и изменение состояния заявки.
- Недопустимое событие: заявка переходит на следующий этап без завершения обязательного предыдущего этапа.

## Внешний источник
Не использован.

## Приоритет
High

Нарушение последовательности может привести к ремонту без согласия клиента или к ложному сообщению о готовности устройства.
